## Demo Script

### Act 1: The Problem (1 minute)

**Presenter narrates:**

> "Meet Ramprasad, a wheat farmer from Madhya Pradesh. He has 50 quintals of wheat ready to sell. Right now, he only knows the price at his local mandi — ₹2,400 per quintal. He doesn't know that:
>
> - A mandi 40 km away is paying ₹2,700
> - A verified processor is buying at ₹2,750 but needs Grade A quality
> - If he stores for just 7 days, prices are forecast to rise to ₹2,850
>
> Without this information, Ramprasad will sell locally and lose ₹15,000 to ₹22,500 in potential earnings. KrishiLink AI solves this."

## Demo Tips

### Do's

- ✅ Start with the problem — make judges empathize with the farmer
- ✅ Show the Hindi interface — it differentiates you from English-only projects
- ✅ Emphasize net realization (not just price comparison)
- ✅ Explain the LLM boundary clearly — judges love this
- ✅ Show voice input — it's a wow moment
- ✅ Keep the demo flowing — no long pauses
- ✅ Have backup: pre-recorded video if network fails

### Don'ts

- ❌ Don't start with architecture slides — start with the story
- ❌ Don't say "this is simulated" apologetically — say "demo data clearly marked, architecture supports real APIs"
- ❌ Don't try to show everything — focus on the farmer flow
- ❌ Don't let a team member fumble with login — use pre-loaded sessions
- ❌ Don't read from slides — speak naturally

### Backup Plan

If the live demo fails:
1. Show pre-recorded video walkthrough
2. Show architecture diagram
3. Show code snippets of recommendation engine
4. Walk through the database schema

### Anticipated Judge Questions

| Question | Answer |
|---|---|
| "Is this using real government data?" | "Our demo uses simulated data clearly marked as such. The architecture has an adapter layer designed to connect to Agmarknet, eNAM, and other real APIs." |
| "How does the AI work?" | "We use LLMs ONLY for understanding Hindi voice queries and generating explanations. All financial calculations — prices, costs, net realization — are deterministic backend code. No LLM does math." |
| "What about internet connectivity in rural areas?" | "Our prototype is web-based. For production, we'd add offline caching and USSD/SMS fallback. The architecture is designed for this extension." |
| "How is this different from eNAM?" | "eNAM provides a trading platform. KrishiLink AI adds intelligent recommendations — we calculate net realization after ALL costs and help farmers choose the BEST option, not just show prices." |
| "How do you verify buyers?" | "Admin-approved verification flow. Buyers submit business details, admin reviews and approves. Unverified buyers are clearly marked. Farmer ratings further build trust signals." |
| "Can this scale?" | "The prototype handles demo-scale traffic. For production, the stateless Express and FastAPI services can scale horizontally behind a load balancer, and PostgreSQL can be replaced with managed RDS." |
| "What about farmer data privacy?" | "Farmer's personal information (phone, exact location) is not visible to buyers until an offer is accepted. RBAC middleware enforces this at the API level." |

## Post-Demo Enhancements to Mention

If judges ask "what's next?":

1. **Real API integration** — Agmarknet, eNAM, Google Maps
2. **Weather data** — factor weather into price forecasts
3. **Regional languages** — extend beyond Hindi to Marathi, Punjabi, Tamil, etc.
4. **Offline mode** — PWA with cached data for low-connectivity areas
5. **WhatsApp bot** — serve farmers via WhatsApp (highest adoption)
6. **Contract farming** — forward contracts between FPOs and processors
7. **Government scheme integration** — show eligible MSP, PM-KISAN, etc.
